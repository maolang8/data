# 제주 크루즈 데이터 연계 가능성 분석

## 1. 결론

2025년 제주 크루즈 승객 설문은 국적, 항구, 조사일, 관광시간, 활동, 소비, 상품 구매 및 만족도를 포함한다. 따라서 다른 데이터와 연계하면 단순 설문 요약을 넘어 다음 질문을 분석할 수 있다.

- 어떤 입항편의 승객이 악천후에 많이 노출되는가?
- 비·강풍이 예상될 때 어떤 활동을 실내 상품으로 전환해야 하는가?
- 크루즈 입항일에 특정 관광지 방문과 지역 소비가 실제로 증가하는가?
- 승객이 원하는 활동과 현재 판매되는 상품 사이에 어떤 공백이 있는가?
- 항구·국적·날씨에 따라 어떤 번들을 추천해야 하는가?

연계 우선순위는 다음과 같다.

| 우선순위 | 결합 데이터 | 판단 |
|---:|---|---|
| 1 | 입항 스케줄 × 시간대별 기상 | 가장 강한 직접 결합 |
| 2 | 크루즈 설문 × 조사일·항구별 기상 | 가능하지만 조사시점 해석 주의 |
| 3 | 입항일 × 관광지 차량도착·방문량 | 행동 변화 검증에 유용 |
| 4 | 입항일 × 지역·업종별 소비 | 일 단위 자료 확보 시 유용 |
| 5 | 설문 수요 × OTA 관광상품 | 수요·공급 격차 분석에 유용 |
| 6 | 관광지 POI × 이동시간·실내외 속성 | 번들 최적화에 유용 |
| 7 | 월별 지역매출 × 월별 입항객 | 참고 수준, 인과 해석 불가 |

## 2. 중심 데이터

### 2025 제주 크루즈 승객 설문

- 표본: 1,014명
- 주요 조인 후보: 조사 월 `SQ2_1`, 조사 일 `SQ2_2`, 조사 항구 `SQ3`, 국적 `SQ4`, 분기 `QUARTER`
- 주요 결과변수: 관광시간, 활동, 교통수단, 상품 구매, 지출, 쇼핑, 불편, 만족도
- 장점: 실제 크루즈 승객만 조사
- 한계: 선박명과 정확한 입·출항시각이 없음

`SQ2_1 + SQ2_2 + SQ3`를 이용하면 항구·날짜 수준의 결합은 가능하다. 그러나 같은 날 같은 항구에 선박이 여러 척 입항했다면 특정 선박에 응답자를 배정할 수 없다.

## 3. 연계안 A: 입항 스케줄 × 시간대별 기상

### 목적

각 선박의 실제 정박시간에 비·강풍·고온·저온이 얼마나 겹쳤는지 계산한다.

### 조인 키

```text
항구 + 입항일시~출항일시
```

### 필요 데이터

- 제주항·강정항 크루즈 입항 스케줄
- 선박명, 입항일시, 출항일시, 승객수 또는 정원
- 기상청 ASOS/AWS 시간별 강수량, 풍속, 기온

기상청은 ASOS/AWS에서 시간·일 단위 기온, 강수, 풍속 등을 제공한다. 제주항에는 제주 북부 관측지점, 강정항에는 서귀포권 관측지점을 대응시키는 방식이 적절하다.

### 생성 지표

```text
정박시간 = 출항일시 - 입항일시
강수노출시간 = 정박시간 중 강수량 > 0인 시간
강풍노출시간 = 정박시간 중 풍속 기준을 넘은 시간
기상위험률 = 위험시간 / 정박시간
위험노출승객 = 승객수 × 기상위험률
```

### 분석 가치

연간 강수시간을 제시하는 것보다 `크루즈가 정박한 시간 중 악천후가 발생한 비율`을 보여주는 것이 훨씬 직접적이다.

### 연결 수준

**직접 결합 가능, 최우선 추천.**

## 4. 연계안 B: 크루즈 설문 × 조사일 기상

### 목적

비가 오거나 바람이 강한 날 조사된 승객과 맑은 날 승객의 활동·지출·만족도를 비교한다.

### 조인 키

```text
2025년 + SQ2_1(월) + SQ2_2(일) + SQ3(항구)
```

### 가능한 비교

- 맑은 날과 비 오는 날의 자연경관 참여율
- 악천후일의 박물관·테마공원 참여율
- 날씨별 쇼핑, 식도락, 실내활동 변화
- 날씨별 관광시간 및 지출 차이
- 날씨별 전반적 만족도와 불편사항

### 주의사항

조사일이 실제 기항일과 동일한지 조사설계 문서를 확인해야 한다. 크루즈 승객은 당일 조사일 가능성이 높지만, 확인 없이 단정하면 안 된다. 또한 조사 시각이 없으므로 시간별 기상은 일 단위로 요약해야 한다.

### 연결 수준

**조건부 직접 결합 가능.** 조사일의 의미를 확인한 뒤 사용한다.

## 5. 연계안 C: 입항일 × 관광지 차량도착·방문량

### 목적

크루즈 입항일에 관광지 방문량이 실제로 증가하는지 검증한다.

제주관광 빅데이터 플랫폼은 관광지·지역별 차량도착, 내비게이션 이동, 방문객 관련 자료를 제공한다. 특정 장소에 대해 일자별 차량도착 수와 이동 패턴을 확보하면 입항일 효과를 비교할 수 있다.

### 조인 키

```text
날짜 + 관광지 또는 읍면동
```

### 분석 설계

```text
관광지 도착수
  ~ 입항 여부
  + 입항 승객수
  + 강수량
  + 기온
  + 요일
  + 공휴일
  + 월 고정효과
```

입항일과 비입항일을 단순 비교하지 말고 같은 요일·계절의 유사한 날짜를 비교해야 한다.

### 추천 관광지

- 강정항 권역: 중문관광단지, 주상절리, 서귀포매일올레시장, 아쿠아플라넷, 미디어아트 시설
- 제주항 권역: 동문시장, 면세점, 용두암, 도심 상권, 박물관

### 한계

차량도착 수에는 일반 관광객과 도민도 포함될 수 있다. 따라서 크루즈 승객 수 자체가 아니라 입항일의 추가 변화로 해석해야 한다.

### 연결 수준

**집계 수준 결합 가능, 행동 검증에 강함.**

## 6. 연계안 D: 입항일 × 외국인 소비 데이터

### 목적

입항일에 항구 주변 및 관광 상권의 외국인 소비가 증가하는지 확인한다.

### 가장 좋은 자료 조건

- 일 단위
- 읍면동 또는 격자 단위
- 외국인 구분
- 국적 또는 대륙 구분
- 업종 구분
- 결제 건수와 금액

제주관광 빅데이터 플랫폼은 외국인 카드 소비, 지역·업종별 소비와 시간대 분석 콘텐츠를 제공한다. 실제 다운로드 가능 범위와 공간·시간 단위를 확인해야 한다.

### 분석 예시

- 강정항 입항일 서귀포시 도심 음식·소매 소비 변화
- 제주항 입항일 면세점·전통시장 소비 변화
- 중국계 선박 입항일 화장품·간식 소비 변화
- 악천후 입항일 실내 업종 소비 증가 여부

### 한계

월 단위 시·군 자료만 확보된다면 특정 입항편의 효과를 분리할 수 없다. 이 경우 매출 인과분석이 아니라 `시장 배경지표`로만 사용한다.

### 연결 수준

**일·읍면동 자료면 유용, 월·시군 자료면 약함.**

## 7. 연계안 E: 설문 수요 × GetYourGuide 상품 공급

### 목적

실제 승객이 원하는 활동과 현재 시장에서 판매되는 상품의 공급 차이를 측정한다.

### 설문 측 수요 변수

- 자연경관 87.0%
- 쇼핑 82.3%
- 식도락 69.2%
- 기항상품 구매 34.7%
- 평균 관광시간 5.11시간
- 언어소통 불편 18.1%

### 상품 측 공급 변수

- 출발 항구
- 가격
- 총 소요시간
- 픽업·항구 복귀보장
- 제공 언어
- 방문 장소
- 실내·실외 비중
- 무료취소 조건
- 날씨 취소 및 대체정책
- 평점과 리뷰 수

### 생성 지표

```text
시간 적합도 = 5.11시간 안에 종료 가능한지
언어 적합도 = 주요 승객 국적 언어 제공 여부
기상 회복력 = 실내 대체코스 또는 전환정책 보유 여부
수요 적합도 = 설문 활동 선호와 상품 구성의 일치도
항구 적합도 = 실제 입항 항구 픽업 가능 여부
```

### 중요한 제한

GetYourGuide는 사전 동의 없는 자동 크롤링을 약관에서 금지한다. 소규모 수작업 표본이나 정식 파트너 API를 사용해야 한다. 가격은 판매 제시가격이고 리뷰 수는 예약량이나 매출이 아니다.

### 연결 수준

**개별 응답자 조인은 불가능하지만 수요·공급 격차 분석 가능.**

## 8. 연계안 F: POI·이동시간·수용력 데이터

### 목적

5.11시간 안에 실행 가능한 코스를 자동으로 조합한다.

### 필요한 변수

- 관광지 위·경도
- 항구에서 이동시간
- 운영시간
- 평균 체류시간
- 실내·실외
- 강수·강풍 민감도
- 수용 가능 인원
- 언어 지원
- 주변 음식·쇼핑시설

### 상품 적합도 예시

```text
상품 적합도
= 수요 일치도
+ 기상 안정성
+ 언어 지원
+ 항구 접근성
+ 주변 소비 연계성
- 왕복 이동시간
- 출항 지연 위험
```

실시간 도로교통 자료가 없더라도 지도 API의 평시 이동시간이나 거리로 1차 분석할 수 있다. 다만 대형 선박 입항 시 전세버스 집중으로 실제 이동시간이 늘 수 있으므로 여유시간을 둬야 한다.

### 연결 수준

**공간 결합 가능, 상품 추천 모델에 적합.**

## 9. 데이터별 역할 정리

| 데이터 | 분석 단위 | 설문과 연결 키 | 알려주는 것 | 한계 |
|---|---|---|---|---|
| 크루즈 승객 설문 | 응답자 | 기준 테이블 | 실제 행동·지출·만족 | 선박명 없음 |
| 입항 스케줄 | 선박·입항편 | 날짜·항구 | 공급 규모·정박시간 | 실제 하선율 부족 |
| ASOS/AWS | 관측소·시간 | 날짜·시간·항구 | 기상 노출 | 관광지 국지기상 차이 |
| 차량·내비게이션 | POI·일 | 날짜·장소 | 실제 이동·방문 | 크루즈 승객 식별 불가 |
| 카드 소비 | 지역·시간·업종 | 날짜·지역 | 소비 변화 | 현금·타 카드 누락 |
| OTA 상품 | 상품·수집일 | 항구·언어·활동 | 시장 공급 | 예약량·매출 아님 |
| 관광지 POI | 장소 | 좌표·항구 | 접근성·대체코스 | 수용력 정보 부족 가능 |
| 부산 중구 월 매출 | 구·월 | 월 | 지역 시장 배경 | 제주 설문과 직접 결합 불가 |

## 10. 추천 통합 분석 모델

### 모델 1. 승객 가중 기상위험

```text
입항편별 위험노출승객
= 입항 승객수
× 정박시간 중 악천후 비율
× 설문상 야외활동 참여율
```

결과는 선박별 위험노출 규모와 실내 대체상품 필요 인원으로 표현한다.

### 모델 2. 소비 방어 시나리오

```text
위험노출 소비액
= 위험노출승객
× 1인당 지출경비 122.1달러
```

```text
대체상품 매출 방어액
= 위험노출 소비액
× 대체상품 전환율
× 소비 회복률
```

전환율과 회복률은 실측값이 없으므로 10%·30%·50% 시나리오로 제시하고 `예상 매출`이 아닌 `가정 기반 방어 가능액`이라고 표시한다.

### 모델 3. 입항일 행동효과

입항일과 유사 비입항일의 차량도착·방문량·소비를 비교해 크루즈 입항이 지역 행동지표에 미치는 추가 변화를 추정한다.

### 모델 4. 다이내믹 번들 추천

입항편의 국적 구성, 남은 관광시간, 기상, 항구, 관광지 이동시간을 입력해 맑은 날 코스와 악천후 대체코스를 동시에 추천한다.

## 11. 현실적인 실행 순서

1. 2025년 제주항·강정항 입항 스케줄 확보
2. 항구별 시간대 기상자료 결합
3. 설문 조사일과 기상자료의 조건부 결합
4. 관광지 15~20곳의 위치·실내외·체류시간 표 작성
5. GetYourGuide 크루즈 전용상품 30~50개 수작업 표본 구축
6. 가능하면 제주 플랫폼의 일별 차량도착 또는 소비자료 확보
7. 입항일 효과와 날씨 대응형 상품 시나리오 산출

현재 데이터만으로 가장 먼저 구현할 분석은 `크루즈 설문 × 2025년 일별 기상`이다. 이후 입항 스케줄을 확보하면 정박시간 기준의 시간대별 분석으로 확장하는 것이 효율적이다.
